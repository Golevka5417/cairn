# App 备案提交前复查清单

> 新备案、每次变更都逐条过一遍。整理自 2026-11 两个 App 的实操。

先回答一个问题：**这个 App 未来一年会做什么？** 上哪些系统、接哪些商店支付、出不出英文、做不做账号、要不要联网、换不换域名。备案写的是「现在 + 已经定了要做的」，不是「现在刚好有的」。

## 〇、名称（最先定）

- [ ] 名字已在 App Store Connect **实际保存成功**
- [ ] 备案名和商店名**一字不差**（空格、英文都算）
- [ ] 查过 App Store 中国区、美区同名
- [ ] 查过商标第 9 类、第 42 类

## 一、应用运行平台

- [ ] 将来要上的系统一次勾全：苹果、安卓、鸿蒙
- [ ] 没勾黑莓、LINUX
- [ ] 安卓包名 ≠ 鸿蒙包名
- [ ] 每个平台的包信息都用证书文件重算过（公钥、SHA-1 / MD5）
- [ ] 安卓签名、鸿蒙发布证书已经提前生成好

## 二、外部 SDK（最容易漏）

- [ ] 上安卓/鸿蒙并收费 → 勾了「支付类」，按将来上的商店勾了厂商
- [ ] 第三方登录、推送、统计、广告、AI 类都想过一遍
- [ ] 自建的邮箱/短信登录、自建同步没当成外部 SDK 填

## 三、服务语言

- [ ] 计划出英文或繁体的，现在就勾上

## 四、域名

- [ ] 每个平台那一栏都填了
- [ ] 域名和备案主体是同一实名
- [ ] 将来要用的同主体域名已经加上
- [ ] 账号、同步、接口这类后端放在已登记域名的子域名下

## 五、备注（服务说明）

- [ ] 只写现状，没有「不联网」「不注册账号」「不收集个人信息」这类绝对否定句
- [ ] 用了「默认」「目前」留余地
- [ ] 没有 AI 功能就没写 AI / Agent / 供第三方调用

## 六、图标

- [ ] 是当前正式版的图标，从项目工程里取，不用桌面上的旧文件

## 七、提交

- [ ] 「保存服务」→「保存订单草稿」
- [ ] 预览页逐项再核一遍
- [ ] 负责人本人做视频核身、输验证码、点「同意承诺书 + 提交审核」
- [ ] 想好初审电话可能问的问题（比如某个域名为什么还没做网站备案）

## 八、最后问自己：未来一年这些会不会发生？

会，就现在写进去；现在写不进去的，记下来攒成一单变更。

| 将来要做 | 影响哪一栏 |
|---|---|
| 上新系统、新商店 | 平台、支付厂商 |
| 收费方式变（订阅、外部支付） | SDK |
| 做账号、第三方登录 | SDK、域名、备注 |
| 出英文版、海外版 | 语言 |
| 换域名、换服务器 IP | 域名、云资源 |
| 开放用户公开发帖、加 AI 生成 | 备注；**必须单独变更**，AI 还要另走算法/大模型备案 |
