# App Store 首次上架全流程

| 适用 | 实测时间 | 总耗时 | 费用 | 状态 | 最后核对 |
|---|---|---|---|---|---|
| iOS（附 macOS 差异） | 2026-10～11，两个 App | 2～6 周，大头在等 App 备案 | 含在开发者年费内 | 实测 | 2026-11-19 |

**一句话结论**：第一次上架，真正卡人的不是审核，是审核前的一串前置——App 备案、名字、协议税务、五样首次必填。按下面的顺序准备，审核本身只要几天。

## 前置条件

1. **苹果开发者账号（组织）**：要有一个能访问的官网和同域名邮箱，苹果会看官网。2026-10 实测提交次日就通过，没有来电。
2. **国内 App 备案**：要在中国大陆上架就必须有，是整条链路最慢的一步，见 [国内 App 备案](04-app-filing.md)。
3. **隐私政策页和技术支持页**：两个公开网址，送审时必填。

## 实际时间线

| App | 备案提交 | 备案通过 | 送审 | 上架 |
|---|---|---|---|---|
| 只此一橘 | 10-19 | 10-29 | 10-31（App + 内购同一份） | 11-04 |
| 犹记 YouText | 11-08 | 11-11 | 11-19（名字和备案对不上，先去掉中国大陆） | 审核中 |

详见 [只此一橘时间线](../timelines/zhiciyiju-2026-10.md)、[犹记时间线](../timelines/youtext-2026-11.md)。

## 要准备的材料

- 开发者账号、Apple Distribution 证书和描述文件
- App 备案号（末尾带 A，例如 `-2A`）
- 隐私政策网址、技术支持网址
- 截图：2026 年起必填栏是「带灵动岛的 iPhone（中等显示屏）」，只收 **1206×2622** 或 1179×2556
- 描述、副标题、关键词、推广文本、审核备注
- 有内购的：每个内购商品一张审核截图
- 审核联系人（姓名、电话、邮箱）

## 步骤

### 1. 签协议、填税务和银行（账号级，只做一次）

在 App Store Connect「协议、税务和银行业务」里签付费 App 协议。**不签付费协议，就不能卖内购。**

- 银行户名填英文，填中文会报无效（2026-10 实测）
- 公司主体在国内的，税表是 W-8BEN-E
- 欧盟 DSA 交易商声明：暂时不上欧盟就选「非交易商」
- 可以顺手申请小型企业计划（佣金 15%），批不批等苹果邮件

### 2. 建 App 记录，名字先占住

在 App Store Connect 新建 App。这一步**备案没过也能先做**，越早越好。

- **App 名称要和备案名一字不差**。顺序是：先在这里实际保存名字 → 存成功了，再拿同一个名字去备案。原因和教训见 [这篇](../pitfalls/app-name-must-match-filing.md)。（2026-11 实测）
- 单独一个常见中文名很可能已被别人的未上架记录占了，商店里搜不到、苹果也不告诉你是谁占的。用 iTunes 搜索接口查不到不代表能用，**以后台实际保存成功为准**。
- 手机和 Mac 用同一个 Bundle ID 的，平台把 iOS 和 macOS 都勾上：一条记录、通用购买、名字一起占。勾了不等于必须交 Mac 版。
- SKU 建完不能改，别带 `-ios` 这类平台后缀。

### 3. 建内购（如有）

- 首个内购**不能单独送审**，要和 App 版本放进同一份草稿。
- **订阅**要三样一起进草稿：每个订阅 + **订阅群组本身**。群组页有自己的「添加以供审核」按钮，只加订阅会报「自动续期订阅必须随其订阅群组一起提交」。（2026-11 实测）
- 页面没加载完时「添加以供审核」是灰的，等几秒。

### 4. 填 App 信息和版本页

- App 信息里填备案号。
- 用了内嵌网页打开任意链接的，年龄分级问卷「无限制网页访问」要选「是」，会被定成 18+。想保 4+，就改成跳系统 Safari。（2026-11 实测）
- App 隐私标签填完要点「发布」。
- 中国大陆有一个「App 合规」页，新 App 要填两条声明（安全评估、AIGC），不填版本页顶上一直有黄条。（2026-11 出现）
- 审核联系人四项不填，版本页的描述和审核备注**保存不上**。（2026-11 实测）

### 5. 新 App 第一次送审：五样必填

新 App 第一次点「添加以供审核」，缺一样就报错：

1. App 信息 → **主要类别**
2. App 信息 → **内容版权**
3. App 信息 → **年龄分级**问卷（7 步，没有对应功能就全选「否」→ 4+）
4. 价格与销售范围 → **定价**：免费也要点一次「添加定价」选 0 元
5. 价格与销售范围 → **供应情况**：默认是空的，不是全球，要自己选

可以直接对照 [首次送审清单](../checklists/app-store-first-submission.md)。（2026-11 实测）

### 6. 打正式包、上传

- **版本号要和工程一致**：App Store Connect 里写「1.0」，工程里 `MARKETING_VERSION` 是「1.0.0」，就选不了这个构建。改工程比改后台省事。
- **用 Release 配置单独编一遍**。只在调试版生效的代码（演示模式之类）如果在 `#if DEBUG` 外面被引用了，调试版能编，正式版 Archive 才报错。发版检查里要有一步 Release 编译。（2026-11 实测）
- 小组件等扩展的版本号要跟主 App 一致（Info.plist 里写 `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)`），否则上传报 `CFBundleVersion Mismatch`。
- 上传报 `App Store Connect access … is required` 或 `Failed to Use Accounts`：Xcode 里的苹果账号登录失效了，隔一两天就可能掉一次。去 Xcode → Settings → Apple Accounts 重新登录。命令行连续失败两次，就直接在 Organizer 点 Distribute App 上传，看到 `Uploaded to Apple` 才算成功。（2026-11 多次遇到）
- 只读权限的 App Store Connect API 密钥什么都改不了（全部 403），想自动化要建「App 管理」角色的密钥。

### 7. 提交审核

- 可能被拦：「提供商名称与 ICP 备案号相关联的名称不符」。账号是英文公司名、备案是中文名时会出现。到「App 信息」页顶部点「确认信息 → 确认」即可。**这是以公司名义作声明，要账号持有人本人点或明确授权。**（2026-11 出现）
- iOS 和 macOS 是两份草稿，分别提交，发布方式（审核后自动 / 手动）也各设各的。
- 有免费额度才出现的付费页，审核备注里写清楚最快怎么到达。
- 「正在等待审核」期间截图区只读。要换图只能先撤回再重新提交（重新排队），或者等下一个版本。

### 8. 上架后

刚上架时在手机 App Store 里搜名字常常搜不到，搜索索引要几小时到一天。先用 `https://itunes.apple.com/lookup?bundleId=<你的 Bundle ID>&country=cn` 确认已上架，再发直链。

## 坑和注意要点（汇总）

| 坑 | 后果 | 怎么避 |
|---|---|---|
| ASC 名称和备案名不一致 | 中国大陆区交不了 | 先占名再备案 |
| 新 App 五样必填缺一样 | 「添加以供审核」报错 | 照清单逐项填 |
| 订阅群组没加进草稿 | 提交报错 | 群组页单独点「添加以供审核」 |
| 版本号 1.0 vs 1.0.0 | 选不了构建 | 改工程 |
| 只编了调试版 | 打正式包才编不过 | 发版检查加 Release 编译 |
| Xcode 账号掉线 | 上传失败 | 每次发版前确认登录，失败改走 Organizer |
| 内嵌网页 | 年龄分级变 18+ | 外链跳 Safari |
| 用了 CloudKit 没部署到正式环境 | 商店版同步全失败 | 控制台 Deploy Schema Changes 到 Production |
